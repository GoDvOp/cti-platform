# Запуск в Docker

Нужны Docker Engine либо Docker Desktop с работающим Linux engine и Docker Compose 2.24+. Python, Neo4j и Python-пакеты на хосте устанавливать не нужно. Команды рассчитаны на Linux, macOS или WSL; выполнять их из распакованной папки проекта. Для первого скачивания базовых образов нужен интернет. Для данных и временного восстановления снимка нужно минимум 256 MiB свободного места; для длительного сбора оставить дополнительный запас.

## Проверка результата без токенов

```sh
sh scripts/docker.sh review
```

Образ собирается, затем проверка выполняется с `network_mode: none`, без `.env` в окружении контейнера и без запуска Neo4j или сборщика. Открыть `data/review/report/report.html`. Проверяются хеш публичного снимка, расчёты на фиксированную дату, аналитический кейс, пилот классификации и статус разметки. Повторный запуск использует тот же снимок; изменённая review-база отвергается. Другой каталог можно выбрать так:

```sh
sh scripts/docker.sh review --output /app/data/another-review
```

После сборки для повторной проверки без скачивания образов:

```sh
docker compose run --rm --no-deps review
```

## Сбор и автоматическое обновление графа

```sh
./start-cti.sh
```

Команда `./start-cti.sh` запускает всё сразу: Neo4j, сборщик и панель. Она работает и при вызове по полному пути из другой папки. После готовности выводится фактический адрес панели, в том числе при изменённом порте.

Скрипт собирает образ, создаёт отсутствующую `.env` со случайным паролем Neo4j, подставляет UID/GID текущего пользователя и запускает Neo4j, сборщик и рабочую панель. Существующая `.env` не перезаписывается. При пустом пароле запуск останавливается с объяснением: заполнить `NEO4J_PASSWORD` минимум восемью символами; рабочий пароль существующей Neo4j менять без отдельной процедуры нельзя.

При отсутствии `data/cti.sqlite3` сборщик проверяет и восстанавливает поставляемый публичный снимок. Это исходный набор на дату снимка, а не новый сбор. Существующая база сохраняется; повторный запуск не восстанавливает поверх неё старые данные. Отдельный кейс ИСП РАН / GitLab добавляется идемпотентно: новые факты не затирают существующие публикации и проверки. Базовый офлайн-снимок остаётся прежним. Если нужен сбор с нуля, до первого запуска установить `CTI_BOOTSTRAP=empty`; будет загружен только каталог компаний. Эта настройка не очищает существующую базу.

Сборщик ждёт готовности Neo4j, формирует первый отчёт по локальным данным, загружает граф и проверяет его обратным чтением; затем опрашивает разрешённые источники по расписанию. Недоступность отдельных источников отражается в статусе и не стирает данные. При временной ошибке Neo4j данные остаются в SQLite, а синхронизация повторяется. Оба основных сервиса перезапускаются после сбоя процесса и перезапуска Docker.

- Рабочая панель: http://127.0.0.1:8766/ ; порт меняется через CTI_WORKBENCH_PORT. [Возможности панели](workbench.md).
- Отчёт и граф: `data/processed/real/report.html`, `data/processed/real/graph_view.html`.
- Состояние сборщика: `data/diagnostics/auto_update/status.json`.
- Аудит загруженной проекции: `data/diagnostics/auto_update/audit.json`.
- Neo4j Browser: http://localhost:7474/browser/ ; логин `neo4j`, пароль из локальной `.env`.
- Для подключения Browser: `bolt://localhost:7687`. Внутри контейнеров используется `http://neo4j:7474`.

Не запускать одновременно сборщик Docker и настольный сборщик на одной папке `data`: они используют общий lock. `./start-cti.sh` также завершает отдельную настольную панель Linux из этой же папки, чтобы после остановки Docker не оставался второй веб-сервер на порту 8765. Команда `./start-cti.sh stop` убирает и ранее оставшуюся настольную панель. Другие проекты и процессы не затрагиваются. Браузер может продолжать показывать уже загруженную страницу, но после обновления сервер будет недоступен.

`./start-cti.sh` и `sh scripts/docker.sh up` автоматически останавливают настольную службу, только если её рабочая папка совпадает с папкой запускаемого проекта. Сборка и проверка конфигурации выполняются до остановки. После успешного запуска контейнеров автозапуск этой службы отключается, чтобы она не конкурировала с Docker при следующем входе в систему. Если контейнеры не запустились, скрипт останавливает контейнер сборщика и восстанавливает ранее работавшую настольную службу; её автозапуск при этом не меняется.

Для перехода с настольного режима используйте указанные скрипты: прямой `docker compose up` не переключает службы на компьютере. При сообщении «Автообновление уже запущено другим процессом» выполните `./start-cti.sh`; файл `worker.lock` удалять не нужно.
Рабочая панель показывает фактический режим сборщика и управляет общей паузой/обновлением в обоих режимах. Запуск и остановка systemd/Docker выполняются командами выбранного механизма; второй сборщик для той же базы не создаётся.

## Управление и сохранение данных

```sh
./start-cti.sh status
./start-cti.sh logs worker
sh scripts/docker.sh cli status
sh scripts/docker.sh cli graph-status
sh scripts/docker.sh cli python scripts/audit_graph.py --sync --repeat
./start-cti.sh stop
```

Команда `stop` оставляет контейнеры и данные. SQLite, отчёты и проверки находятся в bind mount `./data`; Neo4j — в именованном томе `neo4j_data`. Обычный `docker compose down` также сохраняет данные. Удаление томов через `down -v` удаляет проекцию Neo4j. Она восстанавливается из SQLite следующим запуском, но SQLite и `.env` нужно сохранять отдельно. Для согласованной копии SQLite использовать её backup API либо копировать всю папку `data` после остановки сборщика.

Для отдельного экземпляра использовать отдельную копию каталога и другое имя проекта Compose. Если порты заняты:

```sh
COMPOSE_PROJECT_NAME=cti-demo CTI_NEO4J_HTTP_PORT=17474 CTI_NEO4J_BOLT_PORT=17687 sh scripts/docker.sh up
```

Те же переменные надо передавать последующим командам либо сохранить в локальной `.env`. Изменение имени Compose без отдельной папки не изолирует SQLite: bind mount продолжает указывать на `./data`.

Скрипт автоматически задаёт UID/GID для Linux. При ручном использовании Compose задать `CTI_UID` и `CTI_GID` владельца папки `data`. Контейнер приложения работает без root. Код образа не монтируется с хоста, поэтому после изменения кода повторить `sh scripts/docker.sh up` для пересборки и пересоздания контейнера.

## Диагностика

- `permission denied` к Docker: проверить `docker ps` в обычном терминале и права пользователя; скрипт не вызывает sudo и не меняет права сокета.
- Ошибка доступа к `/app/data`: проверить владельца `data` и UID/GID. Папка создаётся скриптом от текущего пользователя.
- Neo4j не становится healthy: посмотреть `sh scripts/docker.sh logs neo4j`; проверить совпадение пароля `.env` с паролем в существующем томе. Не удалять `.env` для исправления этой ошибки.
- Сборщик не становится healthy: посмотреть `logs worker` и `status.json`; проверить lock настольного сборщика и результат аудита. Healthcheck требует свежего heartbeat и успешной синхронизации графа.
- Ошибки отдельных HTTP-источников не равнозначны отказу контейнера; их причины сохраняются отдельно.

Результат контейнерной проверки поставки — в `docs/analysis/release-3.0.0/docker.json`.
