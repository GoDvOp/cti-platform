# Полный граф компаний, продуктов и уязвимостей — версия 1.3

Теперь граф объединяет не только публикации и сигналы, но и продукты, уязвимости, деловые связи, отрасли и домены. Новые сведения извлекаются при сборе и импорте. Каждое существенное утверждение хранится с источником, выдержкой, хешем текста и проверкой.

## Обновление существующего графа

```bash
cd /home/nofear/Проекты/cti-platform
.venv/bin/python -m app.main reindex
.venv/bin/python -m app.main graph-sync
.venv/bin/python -m app.main report
```

reindex переобрабатывает уже сохранённые публикации по текущему словарю продуктов. Он не открывает сайты и сохраняет ручные проверки неизменившихся доказательств. Пароль и существующие публикации не заменяются. Перед расширением создана резервная копия в data/backups/.

В Neo4j Browser выполнить:

```cypher
MATCH path=(c:Company)-[:USES_PRODUCT|USED_PRODUCT|REPORTED_USES_PRODUCT]->(p:Product)
           <-[:AFFECTS|REPORTED_AFFECTS]-(v:Vulnerability)
WHERE c.is_demo = false
RETURN path LIMIT 100;
```

Деловые связи:

```cypher
MATCH path=(a:Company)-[:PART_OF|SUBSIDIARY_OF|SUPPLIES_TO|PARTNERS_WITH]->(b:Company)
WHERE a.is_demo = false
RETURN path LIMIT 100;
```

Полезные дополнительные запросы собраны в graph_queries.cypher. Связь можно нажать в браузере: свойства содержат evidence_url, excerpt, status, age_status и данные проверки. Узлы Assertion показывают само утверждение и ссылку на публикацию через SUPPORTS.

## Как появляются связи

Словарь config/products.json разделяет продукты, например TrueConf Server и TrueConf Client. Простое соседство компании и продукта создаёт только упоминание продукта в публикации. Формулировки «использует», «внедрил», «развернул», «на базе» создают кандидата uses_product; отрицания и планы внедрения исключаются. В длинных или неоднозначных фрагментах связь не угадывается.

Однозначная пара CVE и продукта в предложении об уязвимости создаёт кандидата affects_product. Несколько продуктов или CVE в одном предложении автоматически не спариваются. Формулировки «входит в», «принадлежит», «поставляет», «сотрудничает с» создают кандидатов связей между известными организациями с сохранением направления.

Извлечённые связи получают needs_review. Подтверждение требует отдельной проверки конкретного утверждения. Импорт JSON не может назначить confirmed автоматически. Исключение не скрывается: контрольные примеры knowledge-seed и knowledge-demo подтверждаются явно их отдельной командой с соответствующим именем проверяющего.

| Связь в Neo4j | Интерпретация |
|---|---|
| MENTIONS_PRODUCT | Продукт просто упомянут |
| REPORTED_USES_PRODUCT | Кандидат либо использование с неизвестной датой |
| USES_PRODUCT | Использование подтверждено по источнику не старше 180 дней |
| USED_PRODUCT | Подтверждённое историческое использование, старше 180 дней |
| REPORTED_AFFECTS | Кандидат соответствия CVE и продукта |
| AFFECTS | Бюллетень подтверждает соответствие CVE и продукта |
| PART_OF / SUBSIDIARY_OF | Подтверждённая связь организаций по указанному основанию |
| SUPPLIES_TO / PARTNERS_WITH | Подтверждённая поставка или сотрудничество; не доказательство технического доступа |
| HAS_DOMAIN / IN_SECTOR | Контекст из исходного реестра компаний, status=catalog_context |
| TECHNICAL_CONTEXT | Путь через продукт пока исторический, непроверенный или с неизвестной датой |
| REQUIRES_VERSION_CHECK | Есть свежие основания использования, но недостаточно сведений о версии/диапазоне |
| POTENTIALLY_AFFECTED_BY | Известная версия входит в подтверждённый диапазон; конфигурация и факт уязвимости отдельно не установлены |

REPORTED_PART_OF и аналогичные отношения остаются кандидатами. Само наличие пути не переносит уязвимость на компанию, дочернюю организацию, партнёра или поставщика. Никакого автоматического «заражения риском» по деловым связям нет.

## Версии и проверка

Программа сравнивает точные числовые версии, списки affected_versions и явно заданные affected_ranges с gte/gt/lte/lt. Из fixed_versions диапазон не выводится. Пререлизы, редакции ОС, дополнительные условия и нестандартные версии автоматически не интерпретируются. Даже совпадение версии — повод проверить применимость, а не доказательство уязвимости.

```bash
.venv/bin/python -m app.main knowledge
.venv/bin/python -m app.main exposure
.venv/bin/python -m app.main relation-review ID --status confirmed --reviewer 'Аналитик' --note 'Основание проверки' --confidence medium --basis research_report
```

Для уточнения версии или диапазона создать JSON-список кандидатов по образцу examples/relation.template.json, указать реальную публикацию и её точный фрагмент, выполнить relation-add файл.json, затем relation-review. Изменение исходного текста сбрасывает проверку. Неизменившийся повторный сбор не затирает ручные атрибуты версии.

## Автоматическое обновление

Однократный полный проход:

```bash
.venv/bin/python -m app.main refresh
```

Сбор соблюдает расписание источников. После него переизвлекаются связи, формируется отчёт и выполняется graph-sync. Если Neo4j не отвечает, локальные данные и отчёт сохраняются, ошибка возвращается отдельно. Для локальной проверки без сервера: refresh --no-graph.

Периодический режим:

```bash
.venv/bin/python -m app.main worker --sync-graph
```

При запуске синхронизируется текущий набор, затем новые или изменённые публикации вызывают обновление отчёта и графа. Ошибка Neo4j не останавливает сбор; повтор не чаще раза в минуту. Интервалы самих источников сохраняются. Ручную проверку после изменения можно сразу отразить командой graph-sync. В Docker флаг --sync-graph уже включён; после изменения кода повторить sh scripts/docker.sh up. Инструкция — docker.md.

## Наглядный учебный пример

```bash
.venv/bin/python -m app.main knowledge-demo
.venv/bin/python -m app.main graph-sync --demo
```

В отдельной demo.sqlite3 показаны две вымышленные компании с общим продуктом и поставкой услуг. У Альфы известна учебная версия 1.2.3, у Беты она неизвестна; учебная CVE затрагивает 1.2.3. Для первой выдаётся проверка конфигурации, для второй — проверка версии. В запросах заменить is_demo=false на true. Учебные сущности и CVE имеют отдельную область идентификаторов и не смешиваются с реальными.

## Практические пределы

Система не может узнать закрытый ИТ-стек компании из общего новостного RSS. Требуются публичные кейсы внедрения, сообщения организаций, бюллетени и проверка версий. Новые компании и неизвестные продукты пока добавляются в реестры с устойчивыми ID; произвольный текст не создаёт автоматически подтверждённое юрлицо. Извлечение работает по словарю и ограниченным правилам, не заменяет аналитика и не заявляет полноту.

Расширение графа не меняет формулу Target Interest: технический контекст показывается отдельно. Все 107 тестов и сквозной сценарий проверены локально; выполнение новых запросов на живой Neo4j в среде агента недоступно. Успешный вход и просмотр предыдущего графа ранее подтвердил пользователь.


## Если Neo4j сообщает UnknownLabelWarning: Product

Предупреждение означает, что в выбранной базе ещё нет такой метки. Сначала выполнить graph-sync в терминале, затем graph-status. Новый загрузчик показывает этап, код и сообщение ошибки, а после успешного импорта проверяет наличие Product. При отсутствии ожидаемых продуктов status=ok не возвращается. graph-status выводит реальные количества узлов и типов связей в базе neo4j.

В реальном контрольном примере используются USED_PRODUCT и AFFECTS. USES_PRODUCT или REPORTED_AFFECTS могут ещё отсутствовать: это не требует создания пустых узлов или фиктивных связей. Для контрольного примера достаточно запроса:

```cypher
MATCH path=(c:Company)-[:USED_PRODUCT]->(p:Product)<-[:AFFECTS]-(v:Vulnerability)
WHERE c.is_demo=false
RETURN path;
```

При ошибке загрузки нужен вывод команды graph-sync; повторение читающего MATCH само по себе не загружает модель.
