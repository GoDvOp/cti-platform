# Общий граф: направление и смысл связей

Обзор показывает отношения в направлении действия:

```text
Группировка → атрибуция атаки → Компания → использует / использовала → ПО
     ↓                            ↑
Эксплуатирует CVE по источнику    Сфера → включает компанию
     ↓
    CVE

Группировка → атрибуции в нашей выборке → Сфера
```

Все типы ThreatActor включают не только APT: среди них есть вымогатели,
финансово мотивированные группы и исследовательские кластеры.

## Загрузка и просмотр

В обычном терминале:

```bash
cd /home/nofear/Проекты/cti-platform
.venv/bin/python -m app.main graph-sync
```

После успешной синхронизации в Neo4j Browser:

```cypher
MATCH path=(a:CompanyGraph)-[r]->(b:CompanyGraph)
WHERE a.is_demo=false AND b.is_demo=false
  AND r.company_view=true
RETURN path LIMIT 1000;
```

Фильтр `company_view=true` обязателен для нового обзора. Без него показываются
также исходные связи через инциденты, связи проверки применимости CVE и другие
подробности модели. Старая картинка Browser не обновляется сама: выполните новый запрос.

Русские подписи можно включить, загрузив `docs/neo4j_style.grass` через настройки
стиля Neo4j Browser. Без этого отображаются английские имена типов отношений.

| Направление | Тип отношения | Что установлено |
|---|---|---|
| Сфера → компания | INCLUDES_COMPANY | Классификация из каталога компаний |
| Компания → ПО | USES_PRODUCT / USED_PRODUCT / REPORTED_USES_PRODUCT | Проверенное использование по источнику; исторический или неизвестный период отмечен отдельно |
| Группировка → компания | ATTRIBUTED_ATTACK_ON | Источник связывает группировку с инцидентом, затронувшим компанию; сохраняется характер атрибуции |
| Группировка → компания | CLAIMED_ATTACK_ON | Только заявление об ответственности, отдельно от атрибуции |
| Группировка → CVE | REPORTED_EXPLOITS | Прямое проверенное утверждение actor_exploits |
| Группировка → сфера | OBSERVED_ATTACK_IN_SECTOR | В нашей выборке есть атрибуции атак на компании этой сферы |

Прямые стрелки к компаниям — проекция проверенных путей через один и тот же инцидент.
На стрелке сохраняются `incident_id`, `incident_type`, `assertion_ids`,
`evidence_urls`, `evidence_hashes`, `bases`, `attribution_scopes` и минимальная
уверенность по звеньям доказательного пути. `source_supported` означает наличие
проверенного основания в источниках, а не судебно установленный факт атаки.
Например, FIN7 → Chipotle сохраняет основание `legal_allegation` — опубликованное
обвинение. Публичное заявление группировки не превращается в атрибуцию.

Отмена проверки любого звена или изменение текста доказательства убирают производную
стрелку при следующем graph-sync. Повторная синхронизация пересобирает только
собственные обзорные связи; исходные инциденты и утверждения остаются.

## CVE не принадлежит группировке

CVE описывает уязвимость продукта. Связь группировки с CVE означает эксплуатацию,
описанную источником; одну CVE могут использовать разные группы. Совпадение ПО
компании с уязвимым продуктом не доказывает атаку или использование CVE группировкой.

Обзор не соединяет компанию со всеми CVE её ПО. Проверки версий и техническая
применимость остаются в подробном графе и отчёте. В обзор включена прямая
проверенная связь CL0P → CVE-2023-34362. Другим группировкам CVE из инцидентов
автоматически не приписываются: атрибуция кампании может относиться только к этапу
вымогательства, как у UNC2582 в Accellion, а не к первоначальной эксплуатации.

## Отрасль и частота атак

`OBSERVED_ATTACK_IN_SECTOR` сохраняет число разных инцидентов/кампаний
`incident_count`, число компаний `company_count`, их ID и доказательства.
Кампания FIN7 с тремя компаниями общественного питания даёт одну кампанию и три
компании, а не три независимых наблюдения атак.

Здесь нет автоматического утверждения «часто атакует» или «предпочитает отрасль».
Для него нужны определённый период, достаточное число независимых инцидентов,
покрытие источников и отдельное аналитическое обоснование. Заявления об
ответственности не участвуют в агрегации атрибуций по отраслям.

## Подробный граф инцидентов

Он сохранён отдельно и позволяет проверить основу обзорной стрелки:

```cypher
MATCH path=(c:Company)<-[affected:AFFECTED_ORGANIZATION]-(i:Incident)
           -[attribution:ATTRIBUTED_TO]->(actor:ThreatActor)
WHERE c.is_demo=false AND affected.status='confirmed'
  AND attribution.status='confirmed'
RETURN path LIMIT 150;
```

Полный предметный граф можно посмотреть запросом из `all_knowledge_graph.cypher`.
Обзор не раскрывает весь справочный арсенал группировок из MITRE ATT&CK.
## Дополнение общего обзора

В версии 3.0.0 тот же запрос по метке `CompanyGraph` показывает исследовательский контекст: программы bug bounty, бюллетени, обновления, совпавшие CVE, публикации и источники. Это исходные связи с `company_view=true`, без дублирования в виде предполагаемых атак. `view_layer=research_context` и `source_context` позволяют отделить контекст от прежних связей. Условная гипотеза сохраняет статус, включая `internal_patch_review`; неизвестная версия и закрытый контур не превращаются в доказанную внешнюю уязвимость.
