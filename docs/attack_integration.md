# MITRE ATT&CK — версия проекта 1.6

Enterprise ATT&CK подключён как отдельный версионированный справочник, связанный с существующим графом через проверенные сопоставления. Импортированы официальные STIX 2.1 данные версии 20.0, коллекция изменена 13.10.2026. Прямой сетевой доступ среды агента ограничен; файл получен через GitHub connector fetch_blob из mitre-attack/attack-stix-data. Git blob SHA проверен после сохранения, SHA256 записан в manifest.

## Что загружено

В полном bundle 26 690 объектов, включая отношения, служебные, отозванные и устаревшие записи. Активные справочные сущности: 178 группировок, 747 семейств вредоносного ПО, 95 инструментов, 706 техник/подтехник, 15 тактик и 57 кампаний. Полный исходный набор сохранён в SQLite и data/attack/cache/. Это справочные знания, а не найденные проектом атаки.

Два сопоставления проверены явно с reviewer=assistant_source_review:

| Локальная сущность | ATT&CK | Тип |
|---|---|---|
| TA505 | G0092 | intrusion-set / ThreatActor |
| CLOP ransomware | S0611, Clop | malware / Malware |

Группировка CL0P не сопоставлена с вредоносным ПО Clop. FIN11 не объединяется с TA505. Для остальных локальных группировок отсутствие подходящего объекта в этом наборе не означает отсутствия группировки. Автоматическое совпадение имени/псевдонима создаёт только кандидата; вручную отвергнутый кандидат не предлагается повторно.

В основной граф подготовлено связанное окружение проверенных сопоставлений: 1 справочная группировка, 11 семейств вредоносного ПО, 5 инструментов, 197 техник/подтехник и 14 тактик. Между выбранными объектами 491 исходное STIX-отношение; дополнительно строятся связи техник с тактиками по kill_chain_phases и два ребра ATTACK_MAPPING. Весь справочник не выгружается в основной граф сразу, чтобы сохранять фокус на исследуемых объектах. Нужную группировку можно найти в каталоге и добавить проверенное сопоставление.

## Обновление и воспроизведение

Обновить ATT&CK, затем пересобрать и загрузить общий граф одной командой из обычного терминала:

```bash
/home/nofear/Проекты/cti-platform/.venv/bin/python /home/nofear/Проекты/cti-platform/scripts/check_graph.py --update-attack
```

Этот режим читает официальный index.json, выбирает наибольшую числовую версию Enterprise ATT&CK, скачивает файл и проверяет версию/манифест. При ошибке скачивания или некорректном bundle предыдущий локальный набор сохраняется. Сбор новостных источников и их cooldown не затрагиваются. Обновление ATT&CK запускается отдельно от частого опроса новостей.

Команды CLI из каталога проекта:

```bash
.venv/bin/python -m app.main attack-status
.venv/bin/python -m app.main attack-search TA505
.venv/bin/python -m app.main attack-search PowerShell --kind Technique
.venv/bin/python -m app.main attack-update --version 20.0
.venv/bin/python -m app.main attack-import /путь/к/enterprise-attack.json
```

Для новой установки из архива сначала выполните init, knowledge-seed, knowledge-expand, threat-seed, затем attack-restore. Последняя команда восстанавливает включённый кеш по SHA256 и два явно проверенных сопоставления, если соответствующие локальные сущности существуют. Уже принятые решения аналитика сохраняются. Для нового источника данных используйте attack-import или attack-update; attack-restore намеренно восстанавливает зафиксированную поставляемую версию.

Добавление новой группировки: entity-add загружает каталог локальных сущностей; attack-status показывает кандидатов по именам, attack-search ищет по имени, псевдониму или ATT&CK ID. Решение задаётся отдельно:

```bash
.venv/bin/python -m app.main attack-map LOCAL_ID Gxxxx --status confirmed --reviewer 'Аналитик' --note 'Основание сопоставления с конкретным профилем'
```

LOCAL_ID и Gxxxx замените фактическими ID. Для отказа используйте --status refuted, для очереди проверки --status needs_review. После решения выполните graph-sync. Проверенные имена/псевдонимы и тип объекта входят в fingerprint сопоставления; при их изменении требуется повторная проверка. Отозванная или исчезнувшая цель делает сопоставление неактивным, сохраняя исходное решение и аудит.

## Схема и границы интерпретации

- ThreatActor, Malware, Tool, Technique, Tactic и AttackCampaign получают собственные STIX ID, ATT&CK ID, ссылку, описание, версию объекта и набора, дату изменения и внешние ссылки.
- ATTACK_MAPPING соединяет локальную сущность со справочной без слияния узлов; сохраняет проверяющего, обоснование и хеши снимков.
- ATTACK_USES_SOFTWARE и ATTACK_USES_TECHNIQUE описывают применение по источникам ATT&CK. На ребре сохраняются исходный STIX ID, описание процедуры, ссылки и версия набора.
- SUBTECHNIQUE_OF связывает подтехнику с родительской техникой; IN_TACTIC — технику с тактикой.
- AttackCampaign отделена от наших Incident: известная кампания не создаёт автоматически инцидент компании. Связи attributed-to из STIX сохраняются как ATTACK_ATTRIBUTED_TO.

Справочные отношения имеют status=reported_by_attack. Наличие техники у группировки или её инструмента не доказывает использование в каждом отдельном инциденте. CVE, пострадавшие компании, актуальные версии ПО и подтверждение атак остаются предметом отдельных источников и проверок. Совпадение инструментов/техник не создаёт сотрудничество группировок. Отозванные и устаревшие STIX-объекты исключаются из активной проекции.

Кеш, снимки STIX и сопоставления хранятся отдельно от исходных публикаций и экспертных факторов. Импорт справочника не создаёт сигналы об атаках и не повышает индекс T. Реальный каталог не попадает в demo-граф.
