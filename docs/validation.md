# Проверка поставки 3.1.0

Актуальные машинные результаты находятся в [RELEASE_CHECKS.json](../RELEASE_CHECKS.json) и [release-3.1.0](analysis/release-3.1.0). Они относятся к модели weighted-graph-v3 и фиксированным входам. Протоколы старых выпусков не включаются в текущую поставку.

- Модульные и интеграционные тесты проверяют формулы, доказательства, версии текстов, ручные статусы, даты, неизвестность и отсутствие переноса исторической эксплуатации в текущую применимость.
- Сквозной CLI-сценарий проверяет импорт и повторы, общий граф, справочник ATT&CK, версии, отчёт и отдельный вымышленный пример Shodan.
- Проверка распакованного ZIP запускает офлайн-воспроизведение, три сервиса Docker, общую паузу/обновление, сохранение данных и пароля после пересоздания, повторную сверку Neo4j и остановку панели.
- Реальный Chromium проверяет очередь, поиск, источники, кейсы, исторический пример, прямую ссылку, граф, мобильную ширину и безопасное отображение внешнего текста.
- Проверяются SHA-256 снимка, корпуса, кода извлечения, файлов архива и согласованность отчёта с версией.

Для Shodan дополнительно проверяются повторный импорт, неизвестные даты, отделение наблюдений от утверждений и индексов, ручная принадлежность и её отзыв, контекстная связь в графе, обработка ошибок API и сохранение интервалов запросов. Запросы API в автоматических тестах подменяются; отдельная проверка с действующим ключом описана ниже.

Пилот классификации: 21 совпадение из 30 с исходной проектной разметкой. Это 70% на ограниченном корпусе разработки, не независимая оценка.

Завершённой валидной слепой человеческой разметки извлечения нет. Найденный промежуточный экспорт не использован для расчёта: отмечен один текст из тридцати, и доказательные фрагменты не проходят проверку. Исходный файл сохранён у автора. Precision/Recall/F1 не заявляются; статус отчёта — awaiting_human_labels.

Прогнозная точность и статистическая калибровка весов не измерены. Тесты кода и воспроизводимость не заменяют эту оценку.

Повторить:

```sh
python3 -m unittest discover -s tests
python3 scripts/smoke.py
python3 scripts/review.py
python3 scripts/validate_submission.py
```

Docker-приёмка изолированного архива:

```sh
python3 scripts/check_docker.py /path/to/cti-platform-submission-3.1.0.zip --output /path/to/docker-check.json
```

Скрипт использует отдельные ресурсы и удаляет их после завершения. Папка временных файлов должна иметь не менее 512 MiB свободного места. Рабочие .env, SQLite и контейнеры пользователя не очищаются.


## Рабочее дополнение: автоматическое наблюдение Shodan, 28.10.2026

Это проверка текущих изменений, отдельно от протокола выпуска 3.1.0. Реальный JavaScript панели выполнен в Node с адаптером DOM: выбор домена, включение, приостановка, статус неполной выдачи и отдельный вымышленный пример. Реальный HTTP-обработчик настройки проверен в памяти с проверкой токена и тела запроса.

54 проверки Shodan и автоматизации прошли. После снятия ограничений среды повторный полный прогон завершился успешно: 395 тестов, включая HTTP-тесты. Проверки выполнялись с временной папкой на разделе с достаточным свободным местом. Синтаксис JavaScript и Python проверен.

Ключ из локального `.env` принят методом Shodan `api-info`; значение ключа не выводилось. Реальный запрос Search API в отдельной временной базе вернул HTTP 403: доступ к поиску с текущими правами аккаунта не подтверждён. Успешное получение реальных наблюдений не проверено. Команда `./start-cti.sh` завершилась успешно, Neo4j, воркер и панель имеют статус healthy. Действующая панель возвращает настройки нового модуля через `/api/shodan`. Полная браузерная проверка нового модуля не выполнялась. Архив и протокол старого выпуска не пересоздавались.
