# Панель и автоматическое обновление

Привычный ярлык CTI открывает [браузерную рабочую панель](workbench.md): очередь проверки, источники, доказательства, состояние сбора и последние проверки графа. Разметка по прежнему корпусу остаётся отдельной. Если уже начал разметку, продолжать в прежней вкладке; перенос прогресса выполняется промежуточным JSON.

## Настольный сборщик Linux

Первичная установка из каталога проекта:

```sh
python3 scripts/setup.py
python3 scripts/control_updates.py --install-only
systemctl --user daemon-reload
systemctl --user start cti-platform-update.service
python3 scripts/control_updates.py
```

Устанавливаются пользовательская служба и ярлык. Первый запуск службы выполняется явно; далее автозапуск действует при входе пользователя в Linux. Внешние Python-пакеты не нужны. Служба запускает worker --sync-graph. Перед началом она пытается поднять уже установленную Neo4j через Docker Compose без скачивания образа. Если нужен первый скачиваемый образ, использовать команду Neo4j из README либо полный Docker-режим.

Панель открывается по http://127.0.0.1:8765/ . Она не создаёт второго сборщика. Периодическое обновление соблюдает интервалы, robots и ограничения источников. При новом запуске сначала обновляются отчёт и граф по локальному набору, затем выполняется сетевой сбор. Граф проверяется обратным чтением; ошибка Neo4j сохраняется отдельно и повторяется с задержкой.

В панели доступны общие кнопки:

- «Обновить панель» перечитывает сохранённое состояние.
- «Обновить данные» запрашивает проход сборщика и пересборку графа; интервалы источников не обходятся.
- «Приостановить сбор» завершает текущий проход и сохраняет паузу. «Продолжить сбор» снимает её. Процесс остаётся запущенным и показывает состояние.

Для полной остановки настольной службы:

```sh
systemctl --user stop cti-platform-update.service
```

Чтобы также отключить запуск при входе:

```sh
systemctl --user disable --now cti-platform-update.service
```

Настольная служба рассчитана на включённый компьютер и пользовательскую сессию. После выхода пользователя или выключения компьютера сбор не продолжается.

## Docker-режим

```sh
./start-cti.sh
```

Рабочая панель находится по http://127.0.0.1:8766/ . Сборщик и панель используют тот же файл запросов паузы/обновления. Режим определяется по состоянию самого сборщика, без передачи Docker-сокета панели.

Команда ./start-cti.sh сама остановит настольный сборщик и панель этой же папки. Оба механизма одновременно не используются; lock исключает конкурирующий сбор. Подробные команды, данные, порты и диагностика — [docker.md](docker.md).

## Подтверждения и диагностика

Состояние: data/diagnostics/auto_update/status.json. В нём записаны runtime, фаза, heartbeat, последняя успешная синхронизация и отдельная ошибка. Аудит: data/diagnostics/auto_update/audit.json. Старое успешное подтверждение не считается успешной проверкой нового запуска.

История службы:

```sh
journalctl --user -u cti-platform-update.service -n 30 --no-pager
```

Браузерный граф показывает текущее сохранённое состояние; запрос в Neo4j Browser нужно выполнять заново, чтобы получить новый результат. Наличие читаемого HTML не подтверждает доступность сервера Neo4j.
