# Российские источники — версия 1.2

В config/sources.json теперь пять подключений от трёх издателей/организаций:

| ID | Источник | Что читается | Интервал после успеха / ошибки |
|---|---|---|---|
| securitylab_news | SecurityLab | Официальный RSS новостей | 60 / 15 мин |
| securitylab_analytics | SecurityLab | Официальный RSS аналитики | 120 / 15 мин |
| securitylab_vulnerabilities | SecurityLab | Официальный RSS уязвимостей | 180 / 15 мин |
| securelist_research | Securelist, Касперский | Публичная страница: заголовки, краткие описания и ссылки | 360 / 30 мин |
| nckci_advisories | НКЦКИ | Список уведомлений, до двух JSON-карточек и их явных .json | 360 / 30 мин |

SecurityLab публикует RSS на https://www.securitylab.ru/rss.php. Наличие feed и доступность именно из вашей сети — разные проверки.

Securelist: https://securelist.ru/. В robots.txt на момент проверки для User-agent:* есть Disallow: */feed и */rss, поэтому RSS этого сайта не опрашивается. Не используется подмена User-Agent на GoogleBot/ChatGPT-User. Читается только разрешённая публичная страница с анонсами; полные тексты исследований не обходятся. Карточка без краткого описания сохраняется как title_only, что ограничивает извлечение.

НКЦКИ: https://www.cert.gov.ru/materialy/uyazvimosti/. Разбор ограничен ожидаемыми ссылками на уведомления, затем максимум двумя карточками, помеченными JSON. Файл загружается только по явной .json-ссылке того же разрешённого хоста. PDF, иные вложения и сторонние URL не скачиваются. Если ссылка не найдена или формат изменился, список сохраняется, а источник получает partial с причиной. Из JSON извлекаются буквальные CVE/BDU; продукт, CVSS и факт эксплуатации не угадываются по неизвестной схеме.

Текущая сетевая среда агента по-прежнему не разрешает внешние DNS-имена. Успешный живой сбор не заявляется. Парсеры проверены на явно вымышленных HTML/JSON-копиях и контролируемом транспорте; реальная вёрстка и формат JSON требуют подтверждения первым успешным запуском у пользователя.

```bash

.venv/bin/python -m app.main collect

.venv/bin/python -m app.main report

```

Для одной площадки: collect --source-id securelist_research либо collect --source-id nckci_advisories. Выбор источника не обходит его интервал, robots.txt или Retry-After. Флага принудительного обхода ожидания нет.

## Как читать статусы

- ok — ответ получен и разобран; counts содержит inserted/updated/unchanged. unchanged — нормальный результат повторного прохода.
- partial — данные сохранены частично; смотреть warnings и parse_warnings. Не приравнивать к полностью успешной проверке.
- error — источник не обработан; смотреть error_code, stage, message и next_allowed_at.
- cooldown — нового запроса не было; previous_status и previous_error_code показывают предыдущий исход, wait_seconds — остаток ожидания.
- never_checked — подключение ещё не запускалось.

DNS, HTTP 403/429, таймауты, TLS, запреты robots и неожиданный формат различаются. HTTP 429 Retry-After не сокращается интервалом приложения. Ошибки не печатают пароли, proxy credentials или произвольный текст сервера.

Внутри одного прохода проверяются robots для каждого пути, включая вложения; учитываются маски * и $, отдельные User-Agent и более конкретные Allow. Между запросами внутри источника есть пауза минимум секунду или Crawl-delay. При Crawl-delay больше 10 секунд обработка приостанавливается с явным сообщением, чтобы не удерживать worker длительным ожиданием. При DNS, сетевом отказе, HTTP 403/429 или 5xx для robots.txt сбор приостанавливается. HTTP 404/410 означает отсутствие опубликованного robots.txt; в этом случае продолжается только явно настроенное чтение публичного источника (RFC 9309, раздел 2.3.1.3). Ограничения разных подключений одного издателя пока не объединены в глобальный rate limiter.

## Просмотр графа

После graph-sync в Neo4j Browser:

```cypher
MATCH path=(p:Publication)-[:PUBLISHED_BY]->(src:Source)
WHERE p.is_demo = false
RETURN path LIMIT 100;
```

Для уязвимостей:

```cypher
MATCH path=(p:Publication)-[:MENTIONS_CVE]->(v:Vulnerability)
WHERE p.is_demo = false
RETURN path LIMIT 100;
```

Дополнительные запросы — graph_queries.cypher. Узлы Source и Vulnerability добавлены к прежней модели; Publication теперь показывает title и event_type. Связь MENTIONS_CVE означает только упоминание. Связей «компания уязвима» из этих сведений не создаётся.

## Локальные копии для диагностики

Если сайт открывается браузером, но сборщик возвращает ошибку, можно сохранить разрешённую страницу как HTML и проверить парсер без сети:

```bash
.venv/bin/python -m app.main import-source securelist_research /путь/к/сохраненной_странице.html
.venv/bin/python -m app.main import-source nckci_advisories /путь/к/списку_уведомлений.html
.venv/bin/python -m app.main import-source nckci_advisories /путь/к/уведомлению.json --format json --url https://www.cert.gov.ru/путь/к/исходному_файлу.json
```

Используйте настоящую исходную ссылку опубликованного файла. Происхождение помечается local_file; дата сбора не подменяется датой события. День без точного времени хранится как metadata.publication_day, published_at остаётся null. Для фикстур из tests/fixtures обязательно --demo: они вымышлены и не должны попадать в рабочий набор.

БДУ ФСТЭК, Positive Technologies и другие исследовательские сайты остаются источниками для отдельного разрешённого импорта. Для них в этой версии не заявлен проверенный API или готовый сетевой обработчик. Закрытые TI-платформы не подключаются без соответствующего доступа.

Проверка robots: https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3. Это ограниченная реализация используемых правил, а не заявление о полном соответствии всем деталям RFC.
