# Как попробовать определить потенциальные цели

Текущая задача — получить проверяемую гипотезу на ближайшие 30 дней. Экспертные баллы и условная применимость не являются измеренной вероятностью будущей атаки.

## Какие основания нужны

1. Определить небольшую группу компаний и фиксировать покрытие источниками. Компания с подробным публичным стеком не должна автоматически выглядеть опаснее компании, о которой почти ничего не известно.
2. Найти датированное основание использования продукта. Сохранить точную версию, конфигурацию и доступность, когда они прямо раскрыты. Не выводить стек из списка возможных багов программы bug bounty.
3. Связать продукт со свежим бюллетенем. Разделять дату публикации, диапазон затронутых версий и дату обнаружения атак. Исправленная версия не означает, что клиент установил её или остался на старой.
4. Искать отдельное основание интереса: новая кампания, адресное сообщение, эксплуатация именно этой CVE либо релевантная активность в сопоставимой группе. Предпочтение группировки отрасли нельзя выводить из одной жертвы.
5. Собрать путь и перечислить недостающие условия. Учесть контраргументы: закрытый контур, исправление, снятый продукт, неподходящая версия, историческая дата.
6. Сохранить состояние до исхода и наблюдать 30 дней. Для оценки метода заранее задать исход (например, новое подтверждённое публичное сообщение об инциденте), базовый способ отбора и метрики. Отсутствие публичного сообщения не доказывает отсутствие атаки; такие исходы могут оставаться неизвестными.

## Что добавлено в прототип

Команда `python -m app.main monitoring` автоматически сопоставляет проверенное использование ПО со структурированным уведомлением разработчика. Порог актуальности использования — 180 дней, бюллетеня — 30 дней. Неизвестные версии и внешний доступ отмечаются. Подходящая по этим правилам запись остаётся условной гипотезой для проверки аналитиком.

- conditional_monitoring_candidate — есть свежий технический путь, но применимость и интерес атакующих не установлены.
- internal_patch_review — источник сообщает о закрытом контуре; нет основания объявлять его доступным для внешней атаки.
- insufficient_current_evidence — не хватает актуальных дат/оснований; запись не превращается в текущую цель.
- version_outside_reported_range — известная версия вне диапазона уведомления; такой путь исключается.

Это очередь проверки технической применимости, а не полноценный прогноз. Само участие в bug bounty, количество валидных отчётов, максимальная награда и перечень принимаемых классов ошибок не повышают индексы угрозы.

## Конкретная проверяемая цепочка

Официальный [кейс Росзарубежнефти от 16.08.2026](https://trueconf.ru/blog/success-stories/roszarubezhneft-trueconf-server) описывает внедрение TrueConf Server. Официальное [уведомление от 22.10.2026](https://trueconf.com/blog/news/security-patch-for-the-php-service-in-trueconf-server) описывает обновление PHP-компонента. Установленная версия клиента неизвестна. Кейс прямо указывает собственный ЦОД и закрытый контур без внешнего доступа: поэтому решение — проверить обновление внутри контура, а не назвать организацию следующей внешней целью. Текущая конфигурация и факт обновления не проверялись.

Не переносим уведомление TrueConf Server на TrueConf Enterprise только по сходству названий. Отдельное [сообщение от 23.10.2026](https://trueconf.com/blog/update/trueconf-server-5411-5311-php) подтверждает исправленные версии 5.4.11 и 5.3.11. Точные версии, прямо названные исправленными, исключаются из этой гипотезы; диапазоны из номера исправления не угадываются. Не добавляем CVE, если в самом уведомлении нет идентификатора. Не приписываем эксплуатацию какой-либо группировке без отдельного основания.

Примеры открытых программ [Cloud.ru на Standoff](https://bugbounty.standoff365.com/en-US/programs/cloud_ru), [Звук на BI.ZONE](https://bugbounty.bi.zone/companies/zvuk/main) и [официальное объявление Совкомбанка](https://sovcombank.ru/articles/novosti-kompanii/sovkombank-zapuskaet-programmu-poiska-uyazvimostei-na-bi-zone-bug-bounty) сохраняются как исследовательский контекст. Примеры первоисточников помечены отдельно как ручные пересказы. Кроме них, пользовательский запуск подтвердил автоматический сбор 29 записей из трёх новых источников; BI.ZONE Bug Bounty без HTML-данных и новости PT отключены.

## Запуск и просмотр

```bash
.venv/bin/python -m app.main monitoring
.venv/bin/python -m app.main report --output data/processed/research_update
.venv/bin/python scripts/audit_graph.py --sync --repeat
```

Результат: data/processed/monitoring/monitoring.html и monitoring.json. Запросы для Neo4j: potential_targets.cypher. Новые связи контекста включены в CompanyGraph с отдельной меткой слоя и проверяются отдельным сравнением аудита. Актуальная проверка выполняется для модели v3.

## Начать проверку прогностической полезности

```bash
.venv/bin/python -m app.main monitoring --record-snapshot
```

Флаг сохраняет отдельный публичный снимок SQLite-данных, очередь и manifest в data/monitoring_history. Существующая запись не перезаписывается; --as-of с этим флагом запрещён, чтобы не выдавать пересчёт задним числом за прогноз. Повторять после поступления данных, затем через 30 дней размечать исходы. Нужны несколько временных срезов, независимая проверка и сопоставимый контроль; один сохранённый день ещё не измеряет качество прогноза.

## Связь с актуальной новостью по CVE

Автоматически собранная статья BI.ZONE сообщает о попытках эксплуатации CVE-2026-109618 и CVE-2026-109619 в PHP. Отдельный ручной пересказ индексируемого журнала изменений TrueConf связывает обновление Server 5.5.8 с исправлением этих CVE. Для журнала отмечено ограничение: прямая загрузка не отобразила раздел версий, проверен индексируемый фрагмент первоисточника.

В графе можно пройти: компания → известное использование TrueConf Server ← описание обновления → упоминания CVE ← свежая статья BI.ZONE. Это составной путь, а не новое прямое утверждение об атаке на компанию. Сведения об эксплуатации PHP в целом не приписываются всем клиентам TrueConf. Закрытый контур и неизвестная версия остаются ограничениями, несмотря на наличие новости. Запрос № 6 — в potential_targets.cypher.

Приёмка текущей поставки включает загрузку графа, обратное чтение и повторную загрузку без изменения содержимого. Результаты: [Docker-проверка 3.0.0](analysis/release-3.0.0/docker.json).

Законченный разбор гипотезы и условий пересмотра — [TrueConf/PHP](cases/trueconf-php-2026/case.html). Текущие результаты проверок — [validation.md](validation.md).
