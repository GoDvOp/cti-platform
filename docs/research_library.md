Enterprise и Server — разные продукты. Повторный бюллетень одной уязвимости объединяется для одного утверждения об использовании ПО; ссылки на основания сохраняются.

## Обновление Neo4j на этой машине

В обычном терминале Kali выполните:

```bash
/home/nofear/Проекты/cti-platform/.venv/bin/python /home/nofear/Проекты/cti-platform/scripts/check_graph.py
```

Скрипт повторно разбирает локальные публикации, загружает граф и проверяет результат на сервере. Эта новая загрузка из среды агента не выполнена: Docker и локальные порты недоступны. Сохранён предыдущий успешный журнал пользователя.

В Neo4j Browser выберите базу neo4j. Все связи компаний с продуктами:

```cypher
MATCH path=(c:Company)-[r]->(p:Product)
WHERE c.is_demo = false
  AND type(r) IN ['USES_PRODUCT','USED_PRODUCT','REPORTED_USES_PRODUCT']
RETURN path LIMIT 100;
```

Компании, общий продукт и бюллетени:

```cypher
MATCH path=(c:Company)-[r]->(p:Product)<-[a]-(v:Vulnerability)
WHERE c.is_demo = false
  AND type(r) IN ['USES_PRODUCT','USED_PRODUCT','REPORTED_USES_PRODUCT']
  AND type(a) IN ['AFFECTS','REPORTED_AFFECTS']
RETURN path LIMIT 100;
```

Если Product ещё отсутствует, сначала завершите импорт командой выше. Отсутствие результата для Enterprise ожидаемо: подходящих бюллетеней для него в библиотеке нет.

## Дальнейший сбор

Добавлены адаптер таблицы бюллетеней и две страницы кейсов TrueConf. Они учитывают robots.txt, интервалы и общий лимит хоста. Встроенная библиотека импортирована отдельно и не выдаётся за результат нового живого сбора. Парсеры проверены локальными HTML-фикстурами; их сетевое выполнение нужно проверить из обычного терминала:

```bash
cd /home/nofear/Проекты/cti-platform
.venv/bin/python -m app.main refresh
```

refresh собирает разрешённые источники, переизвлекает связи, обновляет отчёт и синхронизирует граф при настроенном Neo4j. Ошибки источников и cooldown видны в status. Для новой пустой БД сначала init, knowledge-seed и knowledge-expand.
