# CTI-платформа

Пассивный сбор открытых сообщений, доказательные связи и объяснимая очередь проверки компаний. Выполнена задача № 1 тестового задания «Мыслить как хакер»: основная часть и прототип дополнительной части.

Версия приложения: 3.1.0. Модель: weighted-graph-v3. Индексы — сила оснований для проверки; вероятность атаки и прогнозная точность не заявляются.

## Скачать и запустить у себя

Нужны работающий Docker Engine/Desktop и Docker Compose 2.24+. Python на компьютере не требуется. На Windows команды выполняются в WSL2 с включённой интеграцией Docker Desktop.

Если установлен Git, скачайте проект и запустите его:

```sh
git clone https://github.com/GoDvOp/cti-platform.git
cd cti-platform
./start-cti.sh
```

Без Git можно [скачать ZIP](https://github.com/GoDvOp/cti-platform/archive/refs/heads/main.zip) или выбрать **Code → Download ZIP** на странице репозитория. Распакуйте архив целиком, откройте терминал в папке `cti-platform-main`, где находится `README.md`, и выполните:

```sh
sh start-cti.sh
```

При первом запуске скрипт создаст `.env`, восстановит базу из поставляемого снимка и поднимет сервисы. Дождитесь завершения сборки и сообщения с адресом панели.

Панель: http://127.0.0.1:8766/ . Команда дождётся готовности Neo4j, сборщика и панели и выведет фактический адрес.

```sh
./start-cti.sh status
./start-cti.sh logs
./start-cti.sh stop
```

База и настройки сохраняются. На Linux при переходе на Docker завершаются настольный сборщик и отдельная панель этой же папки; после успешного запуска отключается автозапуск настольного сборщика. После остановки контейнеров панель недоступна. [Данные, порты и диагностика](docs/docker.md).

## Если после повторной установки Neo4j не запускается

На чистой машине проект может работать, а после повторного скачивания на прежнюю машину — долго ждать готовности Neo4j и завершаться ошибкой. Если в логах есть `The client is unauthorized due to authentication failure`, база отклоняет пароль подключения.

Один из сценариев: папку проекта или `.env` удалили, но Docker сохранил том Neo4j. Следующий запуск создал новую `.env` со случайным паролем, а в существующей базе остался прежний пароль. Изменение `NEO4J_AUTH` и обычный перезапуск не меняют пароль уже созданной базы.

Прервите зависшее ожидание через **Ctrl+C**. В папке проекта обновите файлы и запустите восстановление:

```sh
git pull --ff-only origin main
./start-cti.sh repair-neo4j
```

Команда остановит сервисы, сохранит полную резервную копию тома в `data/diagnostics/neo4j-recovery/`, установит пароль из текущей `.env` и снова запустит платформу. Восстановление выполняется в отдельном контейнере без сетевого доступа; обычный Neo4j запускается с включённой авторизацией. Данные базы, SQLite и `.env` сохраняются.

Проверьте результат:

```sh
./start-cti.sh status
```

У `neo4j`, `worker` и `workbench` должен быть статус `healthy`. Панель: http://127.0.0.1:8766/ . Для исправления этой ошибки не нужно удалять `.env`, папку `data` или тома командой `docker compose down -v`.

Если в логах другая ошибка, например `EOFException` при чтении `server_id`, смотрите [диагностику Docker](docs/docker.md). Она требует отдельного разбора; долгая загрузка сама по себе не устанавливает причину.

## Проверка без Docker, токенов и сети

Нужен Python 3.11+ со стандартной библиотекой:

```sh
python3 scripts/review.py
```

Открыть `data/review/report/report.html`. Команда восстанавливает проверенный снимок в отдельную базу. Рабочие `data/cti.sqlite3` и `.env` не используются. Docker-вариант: `./start-cti.sh review`.

## Наблюдения Shodan

В панели откройте **«Наблюдения Shodan»**. Кнопка «Вымышленный пример» показывает формат без запроса к Shodan и без записи в рабочую базу. Можно загрузить сохранённый JSON или JSONL Shodan: ответ host API, список баннеров либо результат поиска с `matches`. До 500 наблюдений, файл до 2 МБ. CLI также читает gzip; ограничение действует и на распакованные данные.

Дата наблюдения хранится отдельно от первого импорта; повторная загрузка не делает старую запись свежей. Совпадение имени хоста с доменом компании создаёт подсказку. Для связи с карточкой компании и графом аналитик сохраняет решение, объяснение и публичную ссылку на основание. Решение можно отозвать. Версия по баннеру и список CVE остаются сведениями стороннего источника: они не устанавливают нынешнюю уязвимость компании и не меняют её индексы. В том числе это относится к CVE с флагом `verified` от Shodan.

Пример в отдельной демонстрационной базе и HTML-отчёт:

```sh
./start-cti.sh cli shodan-demo
```

Откройте `data/processed/shodan-demo/shodan.html`. Все сведения в этом примере вымышлены. Для собственной выгрузки положите файл в `data/imports/shodan.json` и выполните:

```sh
./start-cti.sh cli shodan-import data/imports/shodan.json --output data/processed/shodan
./start-cti.sh cli shodan-list
```

Необязательный API-режим читает существующую запись одного публичного IP через [Shodan Host API](https://developer.shodan.io/api#shodan-host). Добавьте `SHODAN_API_KEY` в локальный `.env`, затем выполните `./start-cti.sh cli shodan-host IP`, заменив `IP` нужным адресом. Ключ не нужно вводить в интерфейсе или сохранять в Git. Доступность данных зависит от учётной записи Shodan. Действуют сохраняемые в базе интервалы: 60 секунд между запросами, час для повторного чтения одного IP; при ошибке — пять минут для IP, при HTTP 429 учитывается `Retry-After`. Переадресации не выполняются.

Приложение не обращается к наблюдаемому хосту и не заказывает сканирование. Shodan не добавлен в автоматический цикл сборщика: API вызывается только явной командой. Без ключа доступны импорт, интерфейс, ручная проверка и отчёт. Реальный ответ API с действующим ключом не проверялся; обработка ответов и ошибок проверена на тестовых данных. [Как Shodan определяет уязвимости](https://help.shodan.io/mastery/vulnerability-assessment).

## Дополнительные команды

```sh
python3 -m unittest discover -s tests
python3 scripts/smoke.py
./start-cti.sh cli status
./start-cti.sh cli graph-status
./start-cti.sh cli graph-scores --include-historical --company equifax --explain
```

Для ручного подтверждения связи нужны доказательный фрагмент, уверенность и тип основания:

```sh
./start-cti.sh cli relation-review ID --status confirmed --reviewer 'Аналитик' --note 'Проверен фрагмент источника' --confidence medium --basis research_report
```

Настольный режим: `python3 scripts/control_updates.py`. Его инструкции находятся в [docs/auto_update.md](docs/auto_update.md). Основной сценарий сдачи — Docker либо офлайн-проверка.

## Состав и ограничения

`app` — обработка и аналитика; `config` — каталоги и настройки; `scripts` — запуск и воспроизведение; `tests` — проверки; `docs/cases` — кейсы; `evaluation` — фиксированные входы оценки; `data` — снимок для воспроизводимого запуска и его метаданные. Отчёты, выгрузки графа и рабочие базы создаются при запуске и не хранятся в Git.

Neo4j — проекция SQLite. Полнота открытых источников, точность извлечения и прогнозная полезность — разные вопросы. Система может пропускать сведения и ошибаться; отсутствие данных остаётся неизвестностью. Активные действия в отношении организаций не выполнялись.

Локальные пароли, рабочие базы, окружения, резервные копии и старые сборки в архив не включаются. Контрольные суммы — в `PACKAGE_MANIFEST.json` и файле `.zip.sha256` рядом с архивом.
